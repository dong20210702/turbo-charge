# v70

### Changelog

1.新增充电采样日志 charge_log.csv：充电中每5秒记录一行，包含电量、电池电压/电流/功率、电池温度、**温度传感器原始读数**、充电器侧电压/电流/协商上限、内核实际接受的恒流上限与实际恒流、满充容量/设计容量/循环次数、本模块写入的电流与策略档位，超过4MB自动轮转

2.新增智能分段充电（SMART_CHARGE）：以 PEAK_CURRENT 为满速基准，低于 STAGE_START 给满速，之后按 70%/45%/25% 逐级降流，把降速点从系统默认的“电量过半”挪到 80% 以后

3.修复强制显示28℃写成无条件：真实温度超过 FORCE_TEMP_MAX（默认45℃）时，自动把真实温度交还给系统，不再继续伪装。此前 45℃ 以上反而一直显示 28℃，系统自身的JEITA过温保护等于完全失效

4.新增真实温度熔断：用 thermal_zone 的原始读数（模块改不到的那个）独立判断，超过 FORCE_TEMP_MAX 立即把电流降到 HIGHEST_TEMP_CURRENT，日志里记为 TEMP-GUARD 档

5.电池充满（status=Full 或电量100%）后停止修改充电参数并交还系统控制，修复“电量已100%但充电器仍在输出”的问题

6.未充电时一律写回真实温度，避免残留的28℃误导用户

7.默认关闭阶梯式充电（STEP_CHARGING_DISABLED=1），这是“峰值只能维持一会儿就掉到10W”的最常见原因

# v69

### Changelog

1.修复运行期间内核节点短暂不可用就退出进程的问题（进程消失后快充彻底失效，只能重启手机）

2.修复温度传感器路径无法回传主函数的问题（一进入温度控制就会因找不到文件而退出）

3.修复“伪”旁路供电配置文件修改时间判断错误，以及由此产生的每轮循环内存泄漏

4.修复写值函数未检查stat返回值、栈上缓冲区长度取自未初始化值的问题

5.修复目录扫描和文件列表写死固定长度上限导致的越界隐患

6.修复温度换算在低于10℃和负温度时算错的问题

7.修复获取前台应用的子线程可能被重复创建、被取消后标志位无法复位的问题

8.修复配置文件读取线程在读取失败时空转烧CPU、inotify漏报后不再重载配置的问题

9.修复配置值超过2147483647时的未定义行为，以及电流配置过小导致内核停止充电的问题

10.修复互斥锁未按标准初始化、未在未充电分支读取电量等问题

11.启动脚本改为单实例+守护重启，程序意外退出会自动拉起，不再出现两个实例互相抢写节点的情况

12.周期性复查只在启动时写一次的内核参数，被系统改回后自动补写，避免拔插充电器后失去快充
